# PM 套件 V3 · 主文档

> 给使用者和 AI 共读的总规矩。先读本文件,再按路由进入对应模块文件。
> 大白话版:这是接需求的规矩——老板一句话进来,到能放心交给开发或 AI 出去,中间过几道关、每道关留什么单子。

---

## 0. 这套件是什么、不是什么

**是**:单个需求从"一句话信号"到"可放心开工"的定义管线,外加产品级事实资产(档案卡、台账、评测集)的管理规矩。

**不是**:项目管理工具、数据分析工具。不排开发计划,不算精确 ROI,不替使用者做判断。

**铁律(全套件唯一不可豁免的规则)**:

> **假设不得默默变成事实。**

任何内容想获得`已确认`身份,只有三条路:用户确认(带证据)、实测结果(带样例)、上游已确认文档。三条路之外全部是假设,假设必须带着假设的标签活着。

---

## 1. 六条第一性原则

1. **流程是按成本递增排序的不确定性消除链。** 想错了改一句话几分钟,原型画错半天,PRD 写错两天,开发做错两周——所以"喊停"的闸门全部前置到便宜的关口。
2. **阶段是不确定性的对应物。** 哪种不确定性不存在,对应的段自动为空:没有 AI 节点就没有阶段 2,不需要申请豁免,也不需要记住"这次可以跳"。
3. **事实只有三种来源**:用户确认(谁/何时/依据)、实测结果(样例与通过率)、上游已确认文档。AI 只登记事实,不制造事实。
4. **原型是表达与澄清工具,不是事实源。** 决策记录比 HTML 可信。
5. **流程重量与决策不可逆性成正比。** 改文案两个动作走完,新 AI 能力七段全过——分级由此推出,不是为了仪式。
6. **每份产物必须有明确消费者。** 没有人消费的文档、没有人跑的清单、没有人引用的 ID,都不该存在。

> **原则兜底(操作指令)**:遇到模板和规则没覆盖的情况,不硬套最近似的模板——回到这六条原则现场推导该怎么做,并把推导理由写进产物,供使用者复核。原则与任何模板细节冲突时,原则优先。判定卡本身就是第一性提问的落地:这是谁的、什么问题、不解决会怎样、为什么是现在。

## 2. 主线全景

```text
需求信号(老板一句话 / 用户反馈 / 数据异常 / 竞品动作)
    ↓
[1] 问题与价值 ──→ 不值得 / 不是现在 → 停,记入台账缓做池
    ↓ (判定卡出口拨三开关:级别 / AI 节点 / 呈现形态)
[2] AI 能力预验证(仅当有 AI 节点;挂载在节点上,不占固定顺序)
    ↓          ──→ 能力不达标 → 该节点降级为规则或人工
[3] 方案选型与功能主线
    ↓
[4] 原型表达与评审对齐   ←──(快车道从需求信号直接切入此处,回填后汇入 [3])
    ↓
[5] 规格沉淀(PRD 含埋点章 + 规则集含 AI 能力规格章)
    ↓
[6] 构建交接(可选,仅当明确构建意图)
    ↓
[7] 验证与回流(一页纸) ──→ 结论与 bad case 喂回台账与评测集
```

**三条贯穿线**(全程机制,不是阶段):
- **状态线**:五种状态 + 证据要求 + 变更许可,见第 7 章。
- **数据线**:现状数据(1) → 真实样例(2) → 评测集与埋点(5) → bad case 回流(7)。
- **风险线**:阶段 1 打标(健康/金融/法律/资金),高风险需求在 2/4/5 各多一道守门。

## 3. 判定与路由(总开关)

阶段 1 的判定卡出口,除了"做 / 缓 / 不做",同时拨三个开关:

| 开关 | 选项 | 判定问题 | 决定什么 |
|---|---|---|---|
| 级别 | S / M / L | S=文案样式参数微调,不碰流程规则;M=已有功能的逻辑改动;L=新功能或新 AI 能力 | 流程长度 |
| AI 节点 | 无 / 辅助 / 核心 | P0 主线里有无"识别 / 生成 / 推荐 / 判断"类动作 | 阶段 2 与 AI 能力规格章是否激活 |
| 呈现形态 | 有界面 / 纯后台 | 用户看得见摸得着吗 | 阶段 4 是画原型,还是降级为流程图 + 数据流表 |

**六种典型需求形态的路径**:

| 需求形态 | 路径 |
|---|---|
| 常规功能(如个人中心记录页) | 1 → 3 → 4 → 5(免 AI 能力规格章) → 6 可选 |
| S 级小改(如改按钮文案) | 变更许可 + PRD 回写,两个动作 |
| AI 核心新功能(如化验单识别) | 1 → 2 → 3 → 4 → 5 → 6 → 7 全程 |
| AI 辅助功能(常规功能里带一个 AI 小节点) | 1 → 3 → 4 → 5,仅对该节点挂预验证任务包 |
| 纯后台 / 数据需求 | 1 → 3 → 4(流程图 + 数据流表) → 5 |
| 老板明天要看东西 | 快车道:假设卡 + 探索原型,回填后汇入 3 |

## 4. 双车道

**标准道**:先确认再表达。按 1 → 2 → 3 顺序锁定事实,再进 4 画原型。

**快车道**:先表达再回填。触发条件:用户说"先出个原型看看 / 明天要演示 / 别问了先画"。规则:

1. 前置只有一个动作:AI 把本该问的问题写成**假设卡**(10 行以内:目标用户、P0 主线 3-5 步、终端环境、视觉风格、AI 节点假设),每行状态一律`演示假设`,写完直接开画,不等确认。
2. 产出 `原型-探索版v0.html`,页面内带可见水印"**探索版 · 假设未回填**"。
3. **三禁令**:探索原型不得直接进入阶段 5;原型里 mock 的 AI 效果不算通过预验证;方向被认可后、第二次迭代之前,必须逐行回填假设卡(点头的行转`已确认`并记证据,推翻的行改掉,没提到的保持`待确认`)。
4. 回填完的假设卡即主线卡的种子,从此汇入标准道阶段 3,水印摘除。

快车道没有跳过任何关口,它只是用一次演示替代了一轮提问,把确认动作延后集中完成。铁律照常生效。

## 5. 七段速查表

| 段 | 回答的问题 | 产物 | 硬闸(不过不得进下游) | 详见 |
|---|---|---|---|---|
| 1 问题与价值 | 这是谁的什么事,值得现在干吗 | 需求判定卡(含三开关与高风险打标) | 结论必须是做/缓/不做之一;价值栏禁止编造数字 | 01 |
| 2 AI 能力预验证 | AI 在真实输入上够不够格 | 预验证任务包 → 结果表回收登记 | 结果表未回收的 AI 节点,不得写入阶段 5 能力规格 | 02 |
| 3 方案选型与主线 | 几种干法选哪个,主路怎么走 | 主线与方案卡 | 主线卡未确认,原型只能是演示假设 | 03 |
| 4 原型与评审 | 所有人看到的是同一个东西吗 | 原型.html + 决策与换版记录 | 改原型必须有变更许可;探索原型未回填不得转正 | 04 |
| 5 规格沉淀 | 能不能无歧义开工 | PRD(含埋点章) + 规则集(含 AI 能力规格章) | 待确认不得写成已确认;成功标准的每个指标必须有对应埋点 | 05 |
| 6 构建交接(可选) | 怎么交出去且可验收 | 构建包 | 无明确构建意图不生成;待验证能力只能 mock 或阻塞 | 06 |
| 7 验证与回流 | 上线后真的成立吗 | 验证回流单(一页) | 不阻塞,但台账挂提醒直到回填 | 07 |

**阶段 2 的特别机制(节点挂载 + 外部执行)**:任何时刻,只要一个 AI 节点进入方案(判定时、选型时、甚至评审中老板临时提出),该节点自动带上`待验证`状态并生成预验证任务包。**本套件只出题和验收,不跑验证**:任务包(能力定义、样例采集要求、事先锁定的判定标准、危险红线、结果表模板)交给用户开新 session 或交给算法同学去跑——在讨论过需求的会话里跑验证,结果是被污染的。结果表带回后,套件登记通过率与危险失败数,节点状态翻为`已验证达标 / 需人工兜底 / 已降级`,样例与实测基线 prompt(连同通过率)归档进评测集。

## 6. 产物、命名与目录

```text
[[产品名]]/
├── 产品档案卡.md          ← 产品级事实源,跨需求共享
├── 需求台账.md            ← 所有需求的总表
├── 评测集/                ← 真实样例、bad case、实测基线 prompt
└── 需求-[[需求名]]/
    ├── 判定卡.md
    ├── 主线与方案卡.md          (快车道时:假设卡.md 回填后升级为此)
    ├── 原型.html               (探索版为 原型-探索版v0.html,带水印)
    ├── 决策与换版记录.md        (含变更许可节、评审记录、换版差异)
    ├── PRD.md                  (含埋点章)
    ├── 规则集.md               (含 AI 能力规格章;无 AI 节点则该章写"无")
    ├── AI能力预验证任务包.md    (仅有 AI 节点时)
    ├── 验证回流单.md            (上线后一页)
    └── 可选:构建包.md / 综合评审页.html
```

**各级别碰哪些文件**:S 级 → 决策与换版记录(一条许可) + PRD 回写;M 级 → 判定卡 + 主线差异 + 决策与换版记录 + PRD/规则集更新;L 级 → 全套。

## 7. 全程机制

### 7.1 状态与证据

五种状态:`已确认` / `待确认` / `演示假设` / `后续不做` / `已降级`(AI 节点专用:验证不达标,降为规则或人工)。

**`已确认`必须带证据:谁、何时、依据什么(原话 / 评审结论 / 结果表编号)。** 没有证据栏的"已确认"视为无效,按`待确认`处理。

### 7.2 ID 体系(八种)

`PAGE / ACT / FLOW / RULE / AI / STATE / OPEN / OUT`。规则:一条 ID 只表达一件事;换版不重排旧 ID,新增用新号;跨文档引用必须用 ID 不用描述。侦察结论、假设等一次性内容用章节承载,不发 ID。

### 7.3 变更许可与重生成

每次修改原型前,在决策与换版记录里先写一节**变更许可**:本次目标、允许影响的 ID、禁止改动的 ID、是否影响主线。许可里有`待确认`项时不得动手。触发以下任一条,停止打补丁、改用**重生成输入包**重出干净原型:同一原型连改 3 轮以上;AI 开始改错已确认内容;HTML 明显膨胀;本次变化影响主线 / 规则 / AI 边界。

### 7.4 材料用途

用户给的截图、旧 PRD、竞品页、测试用例,按六类理解:流程参考 / 视觉参考 / 文案参考 / 业务规则参考 / 反例 / 测试用例。**AI 给出默认理解并标注`待确认`即可继续干活;只有分类分歧会实质改变方案时,才停下来问。**

### 7.5 数据线与风险线

数据线:判定卡引用现状数据 → 任务包收真实样例 → 规格沉淀定评测集与埋点 → 上线后 bad case 回流评测集。实测通过的基线 prompt 连同通过率登记,构建交接时作为"实测基线"移交。

风险线:判定卡打标`高风险`(健康 / 金融 / 法律 / 资金)后——阶段 2 任务包必含危险红线(如编造数值一票否决);阶段 4 评审必须演示人工兜底路径;阶段 5 必须终审责任边界与免责表达。

### 7.6 防伪栏

价值判断只允许定性描述 + 引用已有数据,没有数据就写"无数据,依据是……"——宁可粗糙,不可虚假。演示占位只活在原型展示层,不得进入 PRD、规则集、构建包。没有真实来源的风险、阻塞、待确认项,写"无",不为显得完整而编造。

## 8. 产品级资产

| 资产 | 是什么 | 谁读 | 谁写、何时写 |
|---|---|---|---|
| 产品档案卡 | 产品的户口本:已有页面清单、关键规则索引、不可动的存量能力、默认终端环境与视觉风格 | 每个需求开工时(判定卡引用它查存量影响) | 每个需求结项时把新确认的事实写回 |
| 需求台账 | 所有需求一张表:需求 / 级别 / 当前阶段 / 状态 / 卡在谁 / 下一步。收编缓做池、异步等待项(等法务 / 等老板)、中止归档 | 使用者每天看,回答"我该干哪个、催谁" | 每次阶段流转时更新一行 |
| 评测集/ | 考 AI 的题库:任务包样例、线上 bad case、实测基线 prompt 与通过率 | 阶段 2 出题、阶段 5 定规格、算法同学 | 阶段 2 回收时、阶段 7 回流时 |

## 9. 常见错误与修正

| 错误 | 修正 |
|---|---|
| 老板一句话直接画原型(且不是快车道) | 退回判定卡 |
| 快车道原型没回填就开始写 PRD | 停,先逐行回填假设卡 |
| AI 把推断写成`已确认` | 查证据栏,无证据一律降回`待确认` |
| demo 用理想样例验证 AI 能力 | 重开任务包,样例必须含脏数据与"根本不是目标物"的图 |
| 局部反馈被扩成全局重写 | 回到变更许可,只改允许影响的 ID |
| 为了文档完整编造风险 / 数字 | 删掉,写"无"或"无数据,依据是……" |
| 演示占位混进规则集 | 删除或标`演示占位`,占位不下游继承 |
| 小需求被拉着走全流程 | 回判定卡查级别,S 级两个动作走完 |
| 没有构建意图生成了构建包 | 停在规则集,构建包只在明确要交付时生成 |
| 上线后从不回填验证回流单 | 台账挂提醒;连续多个需求不回填,说明成功标准写得没人在乎——回阶段 3 反思 |

## 10. 上手路径

1. 读 `examples/` 里的完整示例(化验单识别 + 膳食建议,L 级全程 + 一个 S 级反例)。
2. 拿一个真实需求,从判定卡开始填。
3. 之后每天只看需求台账。
