# 01 · 判定与路由

> 阶段 1 文件。回答:这是谁的什么事?值得现在干吗?走哪条路?本阶段同时维护两份产品级资产:需求台账、产品档案卡。

---

## 一、输入

任何需求信号都从这里进:老板一句话、用户反馈、数据异常、竞品动作、自己的想法。信号越模糊越要走这一段,不允许"一句话直接画原型"(除非用户明确触发快车道,见 04)。

---

## 二、需求判定卡模板

`需求-[[需求名]]/判定卡.md`

```markdown
# [[需求名]] · 判定卡

## 0. 信号原文
[[ 原样保留,不改写成 AI 理解后的版本 ]]
来源:[[ 老板 / 用户反馈 / 数据 / 竞品 / 自发 ]] 日期:[[ ]]

## 1. 问题解读
| 可能含义 | 代表什么问题 | 可能性 |
|---|---|---|
| [[ 2-4 种解释 ]] | [[ 业务目标 / 体验 / 转化 / 规则 / 视觉 / 技术 ]] | 高 / 中 / 低 |

当前最可能目标:[[ ]] (状态:AI 建议 / 待确认 / 已确认)

## 2. 最小确认问题(最多 3 个)
只问影响方向、范围或主流程的问题。

## 3. 价值判断(防伪栏生效)
- 影响谁、多少人、什么频次:[[ 定性 + 引用已有数据;无数据写"无数据,依据是……" ]]
- 不做会怎样:[[ ]]
- 为什么是现在:[[ ]]
> 禁止编造市场规模、转化率等数字。宁可粗糙,不可虚假。

## 4. 存量影响(查产品档案卡)
| 影响的已有页面 / 规则 / 能力 | 影响方式 | 档案卡索引 |
|---|---|---|
| [[ 无则写"无" ]] | | |

## 5. 高风险打标
涉及 健康 / 金融 / 法律 / 资金 之一即标`高风险`:[[ 是 / 否,涉及哪类 ]]
> 打标后:阶段 2 任务包必含危险红线;阶段 4 评审必须演示人工兜底;阶段 5 必须终审责任边界。

## 6. 结论
[[ 做 / 缓做(进台账缓做池,写触发条件) / 不做(写理由) ]]

## 7. 三开关
| 开关 | 本需求 | 判定依据 |
|---|---|---|
| 级别 | S / M / L | S=文案样式参数微调;M=已有功能逻辑改动;L=新功能或新 AI 能力 |
| AI 节点 | 无 / 辅助 / 核心 | P0 主线里有无"识别 / 生成 / 推荐 / 判断" |
| 呈现形态 | 有界面 / 纯后台 | 用户看得见吗 |

## 8. 路径声明
本需求路径:[[ 按主文档第 3 章六形态表写明,如 1→2→3→4→5→6→7 ]]
AI 节点清单:[[ 每个节点一行,初始状态一律`待验证` / 无 ]]
```

---

## 三、三开关判定细则

- **级别拿不准时就高不就低**——L 错按 M 走的代价(漏关)远大于 M 错按 L 走(多花半天)。
- **AI 节点在后续任何阶段冒出来**(选型时决定用 AI、评审中老板临时加),都要回来补第 8 节的节点清单,并自动挂`待验证`,见 02。
- **纯后台需求**阶段 4 不画手机原型,产出流程图 + 数据流表,其余流程不变。

## 六、硬闸(不过不得进下游)

- [ ] 结论必须是 做 / 缓做 / 不做 三选一,缓做必须写触发条件。
- [ ] 价值栏没有编造的数字。
- [ ] 三开关全部拨到位,路径已声明。
- [ ] 涉健康 / 金融 / 法律 / 资金的需求已打高风险标。
- [ ] 存量影响已对照档案卡核过(档案卡不存在则先建)。
- [ ] 台账已加行或更新。

## 七、常见错误

| 错误 | 修正 |
|---|---|
| 判定卡替老板拍板"最可能目标" | 标`AI 建议`,不许写已确认 |
| 为了立项编数据 | 删掉,写"无数据,依据是……" |
| 所有需求都判 L | 对照级别定义,S/M 有自己的快路径 |
| 建了判定卡忘了台账 | 台账是每日入口,判定卡是单需求档案,两个都要 |
