# 05 · 规格沉淀

> 阶段 5 文件。回答:能不能无歧义开工?产出两份:PRD(含埋点章,给人读)、规则集(含 AI 能力规格章,给 AI 和工程转译)。

---

## 一、入场券(缺一不进)

- 主线卡状态`已确认`(带证据)。快车道需求:回填后的主线卡,不收假设卡。
- 原型评审结论为通过 / 有条件通过,决策与换版记录在手。
- 所有 AI 节点状态为`已验证达标 / 需人工兜底 / 已降级`之一——**`待验证`节点存在时,规则集的 AI 能力规格章不得生成**,可以先写 PRD 其余部分。

事实源优先级:用户最新明确指令 > 评审记录 > 主线卡 > 决策与换版记录 > 原型 HTML。冲突时先问用户,不自行裁决。原型里的演示占位、示例数字一律不得写成事实。

---

## 二、PRD 模板

`需求-[[需求名]]/PRD.md`

```markdown
# [[需求名]] · PRD

## 0. 来源追溯
来源判定卡 / 主线与方案卡 / 原型版本 / 决策与换版记录 / 评审结论;状态不一致时以评审后最新口径为准并列出覆盖依据。

## 1. 定位与背景(自然语言,2-4 段)
是什么、为什么做(引用判定卡的价值判断,禁止新编数字)、给谁用。

## 2. 功能总览
| 功能 | 优先级 | 用户价值 | 来源 ID |

## 3. 页面与跳转
页面清单 + 跳转逻辑(引用 PAGE / ACT,不复述像素)。

## 4. 功能处理逻辑
| FLOW-ID | 输入 | 处理 | 输出 | 状态变化 | 异常 | 状态 |

## 5. 业务规则与数据口径
| RULE-ID | 触发 | 判定口径 | 输出/影响 | 来源 ID | 状态 |

## 6. AI / 规则 / 人工边界
| AI-ID | AI 负责 | 规则负责 | 人工兜底 | 禁区 | 预验证结论 |
> 高风险需求在此终审责任边界与免责表达,写清"AI 不得做什么"。

## 7. 状态、异常与兜底

## 8. 埋点章(新增,成功标准的落地)
| 指标(来自主线卡成功标准) | 埋点事件 | 触发时机 | 上报字段 | 用于哪次验证 |
|---|---|---|---|---|
> 成功标准里的每个指标必须在本表有对应行,对不上就回主线卡改成功标准。本章是阶段 7 回流单的数据源。

## 9. 本版不做 / 待确认
真实来源才记,没有写"无"。

## 10. 风险、合规与责任边界
```

**PRD 不写**:API、DB schema、模型参数、prompt 全文、像素级 UI——分别归工程契约、算法设计、原型。

## 三、规则集模板

`需求-[[需求名]]/规则集.md`

```markdown
# [[需求名]] · 规则集

## 0. 来源追溯 + ID 注册表
八类 ID(PAGE/ACT/FLOW/RULE/AI/STATE/OPEN/OUT)逐条登记:ID / 名称 / 状态 / 来源文件。不许只写范围。

## 1. 页面规则
| PAGE-ID | 职责 | 入口 | 可见条件 | 读写数据 | 状态 |

## 2. 交互跳转规则
| ACT-ID | 动作 | 条件 | 结果 | 状态变化 | 异常兜底 | 状态 |

## 3. 功能处理规则
| FLOW-ID | 前置 | 输入 | 步骤 | 输出 | 依赖 RULE/AI | 异常 | 状态 |

## 4. 业务与算法规则(一条规则只表达一个判断)
| RULE-ID | 触发 | 输入 | 判定逻辑/公式/阈值 | 输出 | 优先级 | 状态 |
优先级序:合规红线 > 人工确认 > 业务硬规则 > AI 输出 > UI 展示。

## 5. AI 能力规格章(新增;每个 AI 节点一份)
### AI-XX [[节点名]]
| 项 | 内容 |
|---|---|
| 输入分布 | 线上真实输入长什么样(引用任务包样例类型比例) |
| 输出质量定义 | 什么算过 / 可接受 / 危险(沿用任务包锁定的标准) |
| 评测集与通过线 | 评测集位置(评测集/目录) + 通过线(如 ≥85%) + 实测成绩(X/N,结果表编号) |
| 失败预算 | 允许多少比例不达标,超了怎么办 |
| 危险失败容忍 | 高风险场景一律 0,触发即走降级链 |
| 降级链 | AI 失败 → 规则兜底 → 人工兜底,每级用户看到什么 |
| 人工确认环节 | 预验证结论为`需人工兜底`时必填,写在哪一步、确认什么 |
| 成本预算 | 单次调用量级 + 预估频次,量级即可 |
| 实测基线 prompt | 指向评测集归档(含通过率),移交给构建方作起点 |
> 无 AI 节点的需求,本章写"本需求无 AI 节点"一行即可。

## 6. 状态、异常与兜底规则

## 7. 数据流与同步边界(产品层,不写接口)

## 8. 本版不做 / 待确认
OPEN 只进本节,不混入已确认规则。
```

## 四、硬闸

- [ ] 入场券三项齐备,`待验证`节点未放行。
- [ ] 每条规则有来源 ID 和状态;`待确认 / 演示假设`没混进已确认。
- [ ] 成功标准每个指标在埋点章有对应行。
- [ ] 每个 AI 节点的能力规格章填齐,通过线引用了真实结果表。
- [ ] 演示占位没被写成事实;没编造风险和阻塞。
- [ ] 高风险需求:责任边界与免责表达已终审。
- [ ] 无 API / DB / 模型参数 / prompt 全文。

---

## 五、常见错误

| 错误 | 修正 |
|---|---|
| AI 节点还是`待验证`就写规格 | 停,先回 02 收结果表 |
| 能力规格只写"AI 识别化验单" | 按 5 章表逐项补,重点是质量定义和降级链 |
| 埋点章和成功标准对不上 | 两边必须一一对应,对不上回主线卡 |
| 把 PRD 写成营销文案 | 回来源 ID,按页面/流程/规则重写 |
| 待确认伪装成已确认 | 查证据栏,无证据降回 |
