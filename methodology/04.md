# 04 · 原型与评审

> 阶段 4 文件。回答:所有人看到的是同一个东西吗?双入口:标准道(主线卡已确认)、快车道(假设卡随行)。产出:原型 + 决策与换版记录。

---

## 一、双入口

**标准道**:主线卡`已确认`(或明确标注`演示假设`)后进入,正常画。

**快车道**:用户说"先出个原型看看 / 明天要演示 / 别问了先画"即触发。规则:

1. 不提问。AI 把本该问的写成**假设卡**(同目录 `假设卡.md`,10 行以内),每行状态一律`演示假设`,写完直接开画:

```markdown
## 假设卡(探索版随行文件)
| # | 假设 | 内容 | 状态 |
|---|---|---|---|
| 1 | 目标用户 | | 演示假设 |
| 2 | P0 主线(3-5 步) | | 演示假设 |
| 3 | 终端环境 | [[ 优先继承档案卡默认值,继承则标`已确认(档案卡)` ]] | |
| 4 | 视觉风格 | [[ 同上 ]] | |
| 5 | AI 节点假设 | [[ 有则列出,一律`待验证`,原型中为 mock ]] | |
```

2. 产出 `原型-探索版v0.html`,**页面内带可见水印"探索版 · 假设未回填"**(固定角标,老板也看得见)。
3. **三禁令**:探索原型不得直接进阶段 5;mock 的 AI 效果不算通过预验证;方向被认可后、第二次迭代之前必须逐行回填假设卡——点头的行转`已确认`(记证据),推翻的行改掉,没提到的保持`待确认`。
4. 回填后的假设卡升级为主线与方案卡,汇入标准道阶段 3,水印摘除、文件更名为 `原型.html`。

## 二、原型形态(按呈现形态开关)

| 开关值 | 形态 |
|---|---|
| 有界面 · 移动端 | 默认模板:左侧演示控制台(280-340px,只切演示变量,不当导航)+ 手机模型(屏内 390x844) |
| 有界面 · Web 管理端 | 桌面布局原型,浏览器窗口模型,不套手机壳 |
| 纯后台 / 数据 | 不画原型,产出流程图 + 数据流表(仍写决策与换版记录) |

**技术约束(全形态通用)**:单文件 HTML,双击可开;**CSS 必须内联或原生,禁止依赖任何 CDN**——演示现场没网是常态;原生 JS,不用 iframe / postMessage / 构建工具。

**交互要求**:手机(或页面)内主流程可独立点通,不依赖控制台;看起来可点的元素必须有反馈(跳转 / 弹层 / 状态切换 / Toast / 局部更新);正常 / 失败 / 空 / 加载四态覆盖关键流程;AI 节点在界面上显性标出,mock 数据标"演示数据"。

**设计不污染事实**:视觉只改"怎么呈现",不新增"呈现什么"。可以生成:标题、通用按钮文案、空态、布局、明确标注的演示占位。不可以生成:价格 / 积分 / 权益 / 会员等级、健康金融法律判断、AI 结论与评分、业务阈值与权限规则——这些必须来自已确认事实源,缺就留空态或标`待确认`。

**占位标注用用户语言**:手机屏(或页面)内的占位与说明文案,必须用演示对象听得懂的话(如"规则待定"),流程内部术语(阶段 5 / 回填 / 主线卡 / 变更许可)不得出现在演示界面里——内部话留在控制台脚注或决策与换版记录。

## 三、决策与换版记录模板

`需求-[[需求名]]/决策与换版记录.md`——原型的全部产品判断、评审、许可、换版,一份文件管到底。

```markdown
# [[需求名]] · 决策与换版记录

## 0. 文件信息
产品 / 需求 / 当前原型版本与文件名 / 记录更新日期

## 1. 输入材料用途
| 材料 | 默认理解(流程/视觉/文案/业务规则/反例/测试用例) | 采用什么 | 不采用什么 | 状态 |
|---|---|---|---|---|
> AI 给默认理解并标`待确认`即可继续;仅当分类分歧会实质改变方案时才停下来问。

## 2. 页面清单
| PAGE-ID | 页面 | 职责 | 入口 | P0? | 状态 |

## 3. 交互跳转表
| ACT-ID | 当前页 | 动作 | 条件 | 去向 | 异常/空态去向 | 状态 |

## 4. 功能处理表
| FLOW-ID | 流程 | 输入 | 处理 | 输出 | 状态变化 | 异常处理 | 状态 |

## 5. AI / 规则 / 人工判定表
| AI-ID / RULE-ID | 判断点 | 输入 | AI 负责 | 规则负责 | 人工兜底 | 禁区 | 预验证状态 | 状态 |

## 6. 异常与兜底
| STATE-ID | 场景 | 触发 | 用户看到什么 | 系统处理 | 下一步 | 状态 |

## 7. 演示占位边界
| 占位内容 | 位置 | 允许下游继承? (一律"否") |

## 8. 评审记录
| 场次 | 日期 | 参与人 | 结论(通过/有条件/需换版) |
> 评审对象不止老板:L 级和含 AI 节点的需求,过会前先做一轮技术 / 算法可行性会审——AI 画原型没有成本感,必须有人在这里喊贵。

## 9. 反馈清单
| FB-ID | 原话 | 类型(体验/规则/AI边界/数据/UI/范围/PRD回写) | 处理(采纳改原型/采纳不改/待确认/不采纳/后续版本/转PRD回写) | 关联 ID |

## 10. 变更许可(每次改原型前必填一节)
| 许可# | 来源反馈 | 本次目标 | 允许影响的 ID | 禁止改动的 ID | 影响主线? | 触发重生成? | 待确认 |
> 许可中有`待确认`不得动手。只做 PRD 回写的反馈不改 HTML。

## 11. 换版清单
| 变更# | 来源许可 | 改了什么 | 涉及 ID(旧 ID 不重排,新增用新号) | 验收方式 |

## 12. 决策状态变更
| ID | 原状态 | 新状态 | 证据(谁/何时/依据) |

## 13. PRD 回写队列
| 内容 | 来源 ID | 建议写入 PRD 章节 |
```

## 四、重生成机制

触发任一条,停止在旧 HTML 上打补丁,改出**重生成输入包**再重画干净原型:同一原型连改 3 轮以上;AI 开始改错已确认内容;HTML 明显膨胀(废页面/重复函数);本次变化影响主线 / 规则 / AI 边界。

重生成输入包只装高密度事实:主线卡、已确认的 PAGE/ACT/FLOW/RULE/AI/STATE、本次变更许可、锁定不改内容、占位与风格限制、技术约束。旧 HTML 只作视觉参考,不作事实源。

## 五、硬闸

- [ ] 标准道:主线卡已确认或全程标`演示假设`;快车道:假设卡存在且原型带水印。
- [ ] 主流程可独立点通,可点元素都有反馈,四态覆盖。
- [ ] 无 CDN 依赖,断网双击可开。
- [ ] 原型里没有未确认的业务事实(价格/权益/健康结论等)。
- [ ] 每次修改都有变更许可节,旧 ID 未重排。
- [ ] 评审结论与状态变更都记了证据。
- [ ] 高风险需求:评审演示过人工兜底路径。
- [ ] 探索原型未回填前,不得进入阶段 5。

## 六、常见错误

| 错误 | 修正 |
|---|---|
| 快车道画完从不回填 | 水印在就是没回填;阶段 5 模板要求回填后的主线卡作输入,绕不过去 |
| 反馈"再高级一点"直接全局重做 | 追问归类(UI/定位/流程),按许可改 |
| 控制台变成主导航 | 控制台只切演示变量,主流程回到页面内 |
| Web 管理端需求套了手机壳 | 按呈现形态开关换桌面布局 |
| 原型用 Tailwind CDN | 内联样式重出,断网演示是核心场景 |
| 老板口头确认没留痕 | 立刻写进决策状态变更,带谁/何时/原话 |
